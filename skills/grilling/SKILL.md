# Grilling(质询)

把一个模糊的想法 / 计划 / 设计,通过**穷追不舍**的提问,逼出每个决策树分支的答案,直到双方达成共同理解(shared understanding)。

本原语是 `grill-me`、`to-spec` 等场景共用的质询循环——逻辑只存这一处,变体做薄委托。

## 质询纪律

1. **建模成设计树,按轮次(round)推进。** 每个决策都分支出挂在它之下的决策。**前沿(frontier)= 前提都已定的那些决策点**,即现在就能问、不必猜未听答案的问题。**一轮问完整条前沿**,然后停下等用户回答,再进下一轮。
2. **一轮内每题编号,并各附你的推荐答案。** 不是空问,是带着建议问——让对方只需确认或修正,降低认知负担。
3. **每轮答案重塑设计树。** 定下的决策把前沿往外推,解锁原先挂在它下面的问题;重算前沿,问下一轮。答案依赖本轮某个未决问题的题属于**后续轮**,不属于本轮。
4. **事实自查,决策才问人。** 能通过读代码 / 查环境 / 读文件确认的*事实*,自己去查(必要时派子任务去查),不找用户要;只有*决策*(选 A 还是 B、要不要做 X)才交给人,并等其回答。
5. **查证不阻塞整轮。** 一次正在跑的查证本身是一个未定的前置:只有它**下游**的题等结果,其余前沿问题本轮照问,不等。
6. **只在达成共同理解后才开始实现。** 前沿未清空前继续问;清空后把共同理解复述一遍,等用户确认。

## 轮次格式

```
❓ **Q1** - **<问题标题>**: <问题正文,可多段,可含多个选项>

➡️ <你的推荐答案>

---

❓ **Q2** - **<问题标题>**: <问题正文,可多段,可含多个选项>

➡️ <你的推荐答案>
```

## 何时停

前沿为空——设计树的每个分支都被走到,没有任何东西被悄悄假设——即达成共同理解。向用户复述一遍,确认后即结束。(实现门槛见纪律 6,此处不重复。)

## 与其他 skill 的关系

- `grill-me`:用户手动触发的无状态质询,薄包装本原语。
- `to-spec`:用本原语确认 spec 的关键决策。
