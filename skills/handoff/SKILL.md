# Handoff(会话交接)

把当前对话压成一份交接文档,让另一个 agent(或新会话)能不丢上下文地接着干。

本 skill 是**轻量**会话连续性方案——只产一份交接 md,只保留下个 agent 真正需要的恢复信息。

## 交接文档要包含

1. **原始意图**——这个任务/会话一开始想达成什么(保留为创建时原样)。
2. **当前进度**——做到哪了、还差什么。
3. **已确定接口/决策**——骨架级(接口签名、数据模型、关键决策),不含实现体。
4. **避坑墓碑**——踩过的坑、失败过的方案(避免下个 agent 重蹈)。
5. **下一步**——可执行的具体步骤。
6. **文件操作日志**——本会话读过/改过/建过哪些文件(只追加)。

## 纪律

- **不复制已有产物。** PRD / 设计文档 / FEATURE_LIST.md / KNOWN_ISSUES.md / commit / diff 已存在的,交接文档里**只引路径**,不复制内容。交接文档是索引,不是仓库。
- **脱敏。** 密钥、令牌、个人隐私信息移除,不写进交接文档。
- **只保留下个 agent 恢复所需。** 不堆砌已完成的细节;已了结的事一句话带过。

## 产出位置

默认写到 `.agent/handoff/HANDOFF.md`(或项目根 `HANDOFF.md`)。询问用户偏好;若 `.agent/handoff/` 不存在则创建。

## 完成判据

交接文档生成完毕的标志(全部满足):

- [ ] 上述 6 项均包含(原始意图 / 当前进度 / 已确定接口决策 / 避坑墓碑 / 下一步 / 文件操作日志)
- [ ] 已有产物只引路径,未复制内容
- [ ] 已脱敏(无密钥 / 令牌 / 个人隐私)

## 与其他 skill 的关系

- `feature-manager` / `issue-manager` 的状态文件(FEATURE_LIST.md / KNOWN_ISSUES.md)是持久事实源,交接文档只引用它们。
