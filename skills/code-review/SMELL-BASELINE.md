# 坏味道基线(Smell Baseline)

Standards 轴在仓库成文规范之上**固定携带**的一份坏味道清单:Martin Fowler《Refactoring》(《重构》)第 3 章的 12 条 code smell。它的作用是兜底——**即使仓库什么都没成文,这份基线也照样带进评审。**

## 两条约束规则

1. **仓库成文规范优先。** 成文的仓库标准永远赢:仓库规范明确认可的写法,即使基线会把它标出来,也要**压制**对应的 smell 报告,不报。
2. **永远是判断题。** 每条 smell 只是一个贴了标签的启发式("可能是 Feature Envy"),**永远不是硬违反**——违反成文规范才可能是硬违反。和这里其他标准一样,工具已经强制检查的内容跳过不报。

## 12 条基线

每条按 *是什么 → 怎么改* 阅读,逐条对照 diff 匹配。

- **Mysterious Name(神秘命名)**——函数、变量或类型的名字没能揭示它做什么、装什么。→ 改名;若想不出一个诚实的名字,说明设计本身就浑浊。
- **Duplicated Code(重复代码)**——同一种逻辑形状在这次改动的多个 hunk 或多个文件里出现。→ 抽出共享形状,两处都调用它。
- **Feature Envy(依恋情结)**——一个方法取用别的对象的数据比取用自己的还多。→ 把方法移到它所依恋的那些数据上。
- **Data Clumps(数据泥团)**——同样那几个字段或参数总是结伴出现(一个想诞生的类型)。→ 把它们收进一个类型,传那个类型。
- **Primitive Obsession(基本类型偏执)**——用基本类型或字符串顶替一个值得拥有自己类型的领域概念。→ 给这个概念一个自己的小类型。
- **Repeated Switches(重复的 switch)**——对同一类型的同样 `switch` / `if` 级联在改动里反复出现。→ 换成多态,或换成各处共用的一张映射表。
- **Shotgun Surgery(霰弹式修改)**——一次逻辑变更被迫在 diff 里散落改动许多文件。→ 把总是一起变化的东西收进同一个模块。
- **Divergent Change(发散式变化)**——一个文件或模块因为几个互不相关的原因被改动。→ 拆开,让每个模块只因一个原因而变化。
- **Speculative Generality(夸夸其谈通用性)**——为 spec 里并不存在的需求添加抽象、参数或钩子。→ 删掉;等真实需求出现再内联回来。
- **Message Chains(过深嵌套的消息链)**——调用方不该依赖的长链导航 `a.b().c().d()`。→ 把这段行走隐藏在第一个对象上的一个方法后面。
- **Middle Man(中间人)**——一个类或函数几乎只是往下面委托转发。→ 去掉它,直接调用真正的目标。
- **Refused Bequest(被拒绝的遗赠)**——子类或实现者忽略或覆盖了它继承来的大部分内容。→ 放弃继承,改用组合。

> 派 Standards 子代理时,把这 12 条**原文粘进 brief**——子代理没有其他途径拿到它。
