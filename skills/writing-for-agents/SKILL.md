# Writing for Agents(写给 agent 的文档)

凡 agent 消费的文档都适用:一份 skill、一份 `AGENTS.md` / `CLAUDE.md`、一份被指针指向的 doc。包装不同,写法相同——**可预测性(predictability)**是根原则:agent 每次运行走相同的*过程*,而非产出相同的*输出*。下面每个杠杆都为它服务。

**加粗术语**在首次使用处或所在节内就地定义——每个术语全文只有一处权威定义,查词就回到它首次出现的地方,不另设词条清单。

要写的文档本身是 skill 时,再读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md):frontmatter 字段、调用二分(model-invoked / user-invoked)、按调用拆分、路由 skill 都在那里;写别的东西用不上它。

## 上下文指针(context pointer)

**上下文指针**是 agent 上下文中持有的、点名某些上下文外材料并编码触达条件的引用。一份 skill 的 `description` 是它,`AGENTS.md` 里点名某份 doc 的一行也是同一个物件。指针的*措辞*——而非它的目标——决定 agent 何时、多可靠地触达材料;一个必有目标背后是措辞孱弱的指针,就是**方差 bug**:先磨利措辞,仅在磨利失败时才内联材料。

指针做两件事:说明材料是什么,并列出该触发它的**分支(branch)**。**分支**是文档处理的一种情形——不同运行走不同路径;指针的每个字都在每个 turn 付费,所以它挣得比正文更狠的精修:

- **锚词前置**:指针是锚词做调用工作的地方。
- **一个分支一条触发。** 重命名同一分支的同义词是同一条分支写了两遍——折叠它们,只留真正不同的分支。
- **删掉正文已有的身份说明。** 指针只留触发,外加"当其他 skill / 其他文档需要……"的触达条款。

## 两种负载(two loads)

每份文档、每个指针都花掉两种预算之一:

- **上下文负载(context load)**是始终加载的材料在 agent 窗口上的成本:`AGENTS.md` 一行、skill 的 description、任何每 turn 都在耗 token 和注意力的东西,无论它触发与否。
- **认知负载(cognitive load)**是人身上的成本:哪些文档存在、何时该伸手取哪份。人就是索引。不是要最小化的成本——它是人类能动性的价格:在人的判断要紧处花它,在不要紧处移除它。

只经指针触达的材料,付指针那一行就逃掉了上下文负载;完全没有指针的材料,全压在认知负载上。

## 信息层级(information hierarchy)

文档由两类内容构成——**步骤(steps)**(agent 按序执行的动作)和**参考(reference)**(定义、规则、事实,按需查阅)。两者自由混合:全步骤(一份食谱)、全参考(一次评审的规则、本 skill)、或兼有。核心决策是每块内容落在**信息层级**的哪一档——一条按 agent 需要材料的紧迫程度排序的阶梯:

1. **文件内步骤(in-file step)**是主层:agent 按序做什么。
2. **文件内参考(in-file reference)**按需查阅,常是合法的扁平同级集合(一次评审的每条规则在同一档)——好安排,不是坏味道。
3. **披露的参考(disclosed reference)**推到独立文件、由**上下文指针**触达、仅当指针触发时加载;跨度从同目录的兄弟文件,一直到**外部参考(external reference)**——住在任何文档之外、任何文档都可指向。

推得太少,顶层膨胀;推得太多,藏了 agent 真正需要的材料。这股张力就是整个决策。

**渐进披露(progressive disclosure)**是沿阶梯下移(移出主文件、推到指针背后),让顶层保持可读。主要不是 token 优化:它是保护**信息层级**的方式。**分支**是最干净的披露测试:每个分支都需要的内联,只有某些分支够得着的推到指针背后。文档有步骤时,本该披露的文件内参考会埋没步骤,让关注它们变成抛硬币——一个方差杠杆,不只是可读性杠杆。

**就近聚合(co-location)**是文件内的同伴:阶梯决定一块内容*落多深*,就近聚合决定它*落定后旁边放什么*。把一个概念的定义、规则和注意事项归在同一标题下,而非散落各处,让读一处带出它的邻居。测试:文档该读起来像为 agent 写的文档——聚合的材料像,散落的材料不像。(区别于**重复**:重复在两处说同一含义,散落把一个含义碎在多处。)

**蔓生(sprawl)**是这里的失败模式:文档单纯太长,即便每行都鲜活且唯一。注意力在盈余上变薄,每多一行就多一行要保持相关。解药是阶梯:把**参考**推到指针背后,按**分支**或序列拆分,让每条路径只带它需要的。

## 步骤与完成判据(completion criterion)

每个步骤以一个**完成判据**收尾——告诉 agent 工作已完成的条件。两个属性让它成为杠杆:

- **清晰度(clarity)**:agent 能区分完成与未完成吗?一句模糊的边界("理解达成")招致**过早完成(premature completion)**——步骤未真正完成就收手,注意力滑向*已经做完*。前方可见的**完成后步骤(post-completion steps)**提供拉力,判据的清晰度是阻力。按序防守:**先磨利边界**(局部且便宜);仅当边界确实无法更清晰*且*你观察到抢跑时,才拆分序列把后续步骤藏起来——而隐藏只在真实的上下文边界上有效(一次交接或一次子 agent 派发;内联调用会把后续步骤留在上下文里,什么都没清掉)。
- **要求度(demand)**:它要求多少。"每个改动的 model 都被清点"逼出充分工作,"产出一份变更清单"不会。要求度驱动**腿活(legwork)**——agent 在工作内的实地挖掘:读文件、探代码库、挖出它需要的东西而非推给用户。腿活潜伏在措辞里,从不写成自己的步骤,也不受步骤绑定:"每条规则都用到"约束一坨扁平参考,正如"每个步骤都做完"约束一个序列——没有步骤的文档仍可带穷尽性门槛。

最强的判据既**可核对(checkable)**又**穷尽(exhaustive)**。

## 何时拆分

**粒度(granularity)**是你划分文档的精细程度;每切一刀都花掉两种负载之一,所以只在值得时切:

- **按序列(sequence)**:当一个步骤的**完成后步骤**诱惑 agent 草草结束当前步骤时,拆开一串**步骤**。把它们隔到视线之外,驱动当前任务上更多**腿活**。当心反向操作:合并序列会把每个步骤的后续步骤暴露给下一步,招致**过早完成**。
- **按调用(invocation)**:skill 专属,见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 锚词(leading words)

**锚词(leading word)**是一个已活在模型预训练里的紧凑概念,agent 运行文档时用它来思考(*lesson*、*fog of war*、*tracer bullet*)。以 token 重复、从不以句子重复,它积累出分布式定义,用最少的 token 锚定一整片行为,靠的是招募模型已有的先验。自造词若定义清晰也能用,但造出来的词招募不到先验:预训练词免费给你的,你得用定义 token 去付——先找已有的词。

它两度锚定。正文里锚**执行**:每次该词出现,agent 都触达同一行为;在扁平参考里,它把注意力聚焦到一类该找的东西上。指针里锚**调用**:当同一个词活在你的 prompt、你的文档和你的代码库里,agent 把这套共享语言链到材料,更可靠地触达——用你真正想触发时用的锚词去措辞。

找机会用锚词重构。三处展开同一个三元组、指针花一句话比划一个想法——每一段都在乞求折叠成单个 token:

- "快、确定性、低开销" → _tight_(一个 _tight_ 循环)。
- "一个你信得过的循环" → _red_,把一个模糊门槛转成二元可观测状态(循环在 bug 上 _red_,或没有)。

一箭双雕:更少 token,*且*给 agent 更锋利的钩子挂思考。假设每份文档都背着能被锚词退休的重述——去找。

**否定(negation)**是这把杠杆旁边的失败模式:用禁止转向把被禁行为拖进上下文,让它*更*可及,而非更不可及。_别想大象_,大象就是全部;否定是一个弱修饰符,被强激活的概念碾过,所以禁令半读起来像在指示做那件事。提示**正面**:说出目标行为("写单行注释"),让被禁的永不出现在文本里。禁止只在无法正面表述的硬护栏上挣得位置;即便如此也配上正面目标,让注意力落在该做什么上。

## 精修(pruning)

- 让每个含义只住在一个**单一事实源(single source of truth)**处:一个权威位置,改行为只需改一处。**重复(duplication)**(同一含义出现在不止一处)耗费维护和 token,并把含义在层级上的权重抬到超出其真实排序——它是锚词的意外反面:锚词故意重复一个 token,从不重复含义。
- **环境**也是事实源(`package.json` 脚本、配置文件、目录布局、`--help` 输出),复述它的文档是一层**缓存(cache)**:一次查找的副本,只在查找昂贵时才挣得它的负载。缓存 agent 查不到的东西:不成文的约定、某个选择背后的理由、没有任何配置会招供的坑。一次一个文件、一条命令就能查到的,留给环境——那里不会过时。
- 逐行检查**相关性(relevance)**:它还关系到这份文档做的事吗?一行失去相关性,或因为从不关系任务(纯解说,或该披露的分支),或因为过时——随着它描述的行为或世界变化而漂移。更短的文档更容易保持相关。没有精修纪律,默认命运是**沉淀(sediment)**:添加感觉安全、移除感觉危险的过时层越积越厚,直到你得钻透它们才找到还活着的东西。
- 逐句猎**空操作(no-op)**:模型默认就会遵守的指令,付了负载却什么都没说。测试(*它相对默认行为改变了什么?*)是模型相对的,不是读者相对的:两个人争论一句是否 no-op,争的其实是默认,靠跑一遍文档来裁决,不靠辩论。一句没过就删整句,而不是从这句里抠词。这条测试也给锚词打分:一个弱到打不过默认的词(_be thorough_,在 agent 本来就差不多 thorough 时)是 no-op,解药是更强的词(_relentless_),不是换一门技术。

## 审计一份现成的文档

本 skill 的手动用法;每步以完成判据收尾:

1. **逐句跑 no-op 测试。** 一句一句问*相对默认改变了什么*,答不上来就删整句。完成判据:全文每句都过了测试,剩下的每句都能说出它改变的那一点行为。
2. **否定转正面。** 搜"不要 / 避免 / 禁止 / 别",每处问能否改成正面描述目标行为;改不动的才算硬护栏,且已配上该做什么。完成判据:没有一处纯禁止。
3. **检查步骤的完成判据。** 每个步骤收尾的条件可核对吗?要紧处穷尽吗?有模糊边界又露出后续步骤的,就是抢跑点。完成判据:每个步骤的判据要么可核对且穷尽,要么已磨到不可再磨并写明了拆分的理由。
4. **反蔓生。** 哪些参考该推到指针背后?哪些段落只服务某些分支?哪些整段该删?完成判据:每条路径只带它需要的内容,顶层只剩步骤和每条路径都要的参考。
5. **给锚词打分。** 每个重复出现的说法,是招募了先验,还是只是重述?完成判据:每个锚词都能说出它招募的那条先验,或者已被更强的词替换。

## 与其他 skill 的关系

本 skill 是审计所有 agent 文档的**元工具**,自身是用户调用(`disable-model-invocation: true`)——审计是人工发起的判断,不需要 agent 自主触达。

- `grilling`、`tdd`、`code-review`、`implement`、`domain-modeling`、`feature-manager` 等任何 skill,以及 `AGENTS.md` / `CLAUDE.md` 与它们指向的 doc,都可用本 skill 审计:逐句跑 no-op 测试,逐处否定转正面,检查完成判据是否可核对且穷尽,验证锚词是在招募先验还是只是重述。
- 审计产出诊断报告,不直接改被审对象——改不改由其作者决定(与 `code-review` 同纪律)。
