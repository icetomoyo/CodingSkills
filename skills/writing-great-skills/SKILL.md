# Writing Great Skills(写好 skill)

skill 的存在,是为了从一个随机性系统中逼出确定性。**可预测性(Predictability)**——agent 每次运行走相同的*过程*,而非产出相同的*输出*——是根原则;下面每一个杠杆都为它服务。

**加粗术语**在 [`GLOSSARY.md`](GLOSSARY.md) 中有完整定义,需要时查阅。

## 调用方式(Invocation)

两种选择,付出不同的代价:

- **模型调用(model-invoked)** skill 保留 **description(描述)**,agent 能自主触发,其他 skill 也能触达(你仍可手动键入其名)。它贡献**上下文负载(context load)**——描述每个 turn 都占据窗口。机制:省略 `disable-model-invocation`,写面向模型的描述,含丰富触发措辞("当用户想……、提到……时使用")。
- **用户调用(user-invoked)** skill 把描述从 agent 视野中剥离:只有你手动键入其名才能触发,其他 skill 也无法触达。零上下文负载,但付出**认知负载(cognitive load)**——*你*是必须记得它存在的索引。机制:设 `disable-model-invocation: true`;`description` 变为面向人——一句话摘要,触发措辞删尽。

只有当 agent 必须自主触达、或其他 skill 必须触达时,才选模型调用。若它只被手动触发,就设为用户调用,不付上下文负载。

当用户调用 skill 多到你记不住,堆积的认知负载由**路由 skill(router skill)**治愈:一个用户调用 skill,点名其余 skill 及何时触达各自。

## 写描述

模型调用的 **description** 做两件事——说明 skill 是什么,并列出该触发它的**分支(branch)**。每个词都增加**上下文负载**,所以描述比正文更该狠剪:

- **把 skill 的锚词(leading word)前置**——描述是锚词做调用工作的地方。
- **一个分支一条触发。** 重命名同一分支的同义词是**重复(duplication)**——"用 TDD 开发功能……要求测试先行开发"是同一条分支写了两遍。折叠它们,只留真正不同的分支。
- **删掉正文已有的身份说明。** 描述只留触发,外加"当其他 skill 需要……"的触达条款。

## 信息层级(Information Hierarchy)

skill 由两类内容构成——**步骤(steps)**和**参考(reference)**——自由混合:可全是步骤、全是参考、或兼有。核心决策是用哪个、各自落在**信息层级**的哪一档——一条按 agent 需要材料的紧迫程度排序的阶梯:

1. **技能内步骤(in-skill step)**——`SKILL.md` 中的有序动作,主层:agent 按序做什么。每个步骤以一个**完成判据(completion criterion)**收尾——告诉 agent 工作完成的条件。让它*可核对(checkable)*(agent 能区分完成与未完成?),并在要紧处*穷尽(exhaustive)*("每个改动的 model 都被清点",而非"产出一份变更清单")——模糊的判据招致**过早完成(premature completion)**。
2. **技能内参考(in-skill reference)**——`SKILL.md` 中的定义、规则或事实,按需查阅。常是合法的扁平同级集合(一次评审的每条规则在同一档)——好安排,不是坏味道。*本 skill 全是参考。*
3. **外部参考(external reference)**——参考推到 `SKILL.md` 之外、由**上下文指针(context pointer)**触达、仅在指针触发时加载的文件(从*披露的*参考——如 `GLOSSARY.md` 同目录文件,仍属本 skill——到完全外部参考,住在 skill 系统之外、任何 skill 都可指向)。

要求高的完成判据驱动充分的**腿活(legwork)**——agent 在工作内的实地挖掘,无论 skill 有无步骤,因为"每条规则都用到"约束扁平参考,正如"每个步骤都做完"约束序列。推得太少则顶层膨胀;推得太多则藏了 agent 真正需要的材料。这股张力就是整个决策。

**渐进披露(progressive disclosure)**是沿阶梯下移——从 `SKILL.md` 推到链接文件——让顶层保持可读。机制:skill 目录下一个链接的 `.md` 文件,以所含内容命名(本 skill 把完整定义披露到 `GLOSSARY.md`)。有些 skill 有多种用法,每种不同用法是一个**分支**——不同运行走不同路径。分支是最干净的披露测试:每个分支都需要的内联,只有某些分支触达的推到指针背后。**上下文指针**的*措辞*——而非目标——决定 agent 何时、多可靠地触达材料。

阶梯决定一块内容*落多深*,**就近聚合(co-location)**决定它*落定后旁边放什么*:把一个概念的定义、规则和注意事项归在同一标题下,而非散落各处,让读一处带出它的邻居。

## 何时拆分

**粒度(granularity)**是你划分 skill 的精细程度,每次切分都付出两种负载之一,所以只在值得时切。两种切法:

- **按调用**——当你有一个独立**锚词**该单独触发,或其他 skill 必须触达时,切出一个**模型调用** skill。你为新描述付**上下文负载**,所以独立触达必须值这个价。
- **按序列**——当一个步骤的**完成后步骤(post-completion steps)**诱惑 agent 草草结束当前步骤(**过早完成**)时,切分一串**步骤**。把它们隔到视线之外,鼓励 agent 在当前任务上多做**腿活**。

## 精修(Pruning)

让每个含义只住在**单一事实源(single source of truth)**:一个权威位置,改行为只需改一处。

逐行检查**相关性(relevance)**:它是否仍关系到 skill 做的事?

然后逐句猎杀**空操作(no-op)**——不是逐行,是逐句:对每个句子单独跑 no-op 测试——*这句话相对模型的默认行为,改变了什么?* 答不上来就删整句,而非从中抠词。要狠——多数没通过的散文该走,不是重写。

## 锚词(Leading Words)

**锚词(leading word)**是一个已活在模型预训练中的紧凑概念,agent 运行 skill 时用它来思考(如 *lesson*、*fog of war(战争迷雾)*、*tracer bullet(曳光弹)*)。在文本中重复(虽不一定——强锚词可能只需出现一次),它积累出分布式定义,以最少 token 锚定一整片行为,靠的是招募模型已有的先验。

它两度服务可预测性。在正文中锚定*执行*:每次该词出现,agent 都触达同一行为。在描述中锚定*调用*:当同一个词活在你的 prompt、文档和代码中,agent 把这套共享语言链到 skill,更可靠地触发。

找机会把 skill 重构为使用锚词。三处展开同一个三元组(**重复**)、描述花一句话比划一个想法——都是 begging to **折叠(collapse)**成单个 token 的段落。例如:

- "快、确定性、低开销" → _tight(紧凑)_——把一个阶段里重述的同一品质收进一个预训练词(一个 _tight_ 循环)。
- "一个你信得过的循环" → _red(红)_——把一个模糊门槛转成二元可观测状态(循环在 bug 上 _red_,或没有)。

一箭双雕:更少 token,*且*给 agent 一个更锋利的钩子挂思考。假设每个 skill 都背着能被锚词退休的重述——去找。

## 失败模式

用来诊断 skill 可能出的问题:

- **过早完成(premature completion)**——步骤未真正完成就结束,注意力滑向"完成"。防御,按序:先磨利完成判据(便宜、局部);仅当它无法更清晰*且*你观察到抢跑时,才通过拆分隐藏完成后的步骤(序列切法)。
- **重复(duplication)**——同一含义出现在不止一处。耗费维护和 token,并把含义在层级上的权重抬到超出其真实排序。
- **沉淀(sediment)**——因添加感觉安全、移除感觉危险而沉积的过时层。任何缺乏精修纪律的 skill 的默认命运。
- **蔓生(sprawl)**——skill 单纯太长,即便每行都鲜活且唯一。伤可读性和可维护性,浪费 token。解药是阶梯:把**参考**推到指针背后,按**分支**或序列拆分,让每条路径只带它需要的。
- **空操作(no-op)**——模型默认就会遵守的行,你付负载说了等于没说。测试:*它相对默认改变了行为吗?* 太弱的锚词(_be thorough_ 而 agent 本来就差不多 thorough)是 no-op;解药是更强的词(_relentless_),不是换技术。
- **否定(negation)**——用禁止转向会反噬:_别想大象_反而把大象拉进语境,让它更可及。**否定→正面**:提示*正面*——描述目标行为("写单行注释")让被禁的永不出口;只在无法正面表述的硬护栏上保留禁止,即便如此也配上该做什么。*审计时逐句找"不要/避免/禁止"——每处都问:能否改成正面描述目标行为?*

## 与其他 skill 的关系

本 skill 是审计所有其他 skill 的**元工具**。它本身是用户调用(`disable-model-invocation: true`),因为审计是手动发起的判断,不需 agent 自主触达。

- `grilling`、`tdd`、`code-review`、`feature-manager` 等任何 skill 都可用本 skill 审计:逐句跑 no-op 测试,逐处否定转正面,检查完成判据是否可核对且穷尽,验证锚词是在招募先验还是 merely 重述。
- 审计产出诊断报告,不直接改被审 skill——改不改由其作者决定(与 `code-review` 同纪律)。
